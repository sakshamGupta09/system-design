# API Design Template

1. Start from the user intent. What are the users trying to do?
2. Users want to shorten their URLs, visit the original URL and view analytics.
3. Create endpoints to enable users to do these activities. 

## 1. Create a short URL

**Endpoint:** `POST /api/shorten`

**Request Body:**

```json
{
  "longUrl": "https://example.com/products",
  "alias": "summer-sale"
}
```
- `longUrl` (required): Original URL. Must be valid.
- `alias` (optional): Custom alias. If omitted, system generates one automatically.
- **Why POST?** Creates a new short URL resource.

**Success Response (201 Created):**

```json
{
  "shortUrl": "https://short.url/abc",
  "longUrl": "https://example.com/products",
  "createdAt": "2026-11-17T06:30:00Z",
  "expiresAt": null
}
```

## What happens if multiple users try to short the same URL

- **Option 1** is to generate short URL for every user because they want their isolated analytics. But this uses more storage.
- **Option 2** is to return the same already shortened URL. Here we save, space and resources but multiple users share the analytics.
- If analytics is more important, go with Option 1.

## 2. Visit the URL

- **Endpoint:** `GET short.url/abcd`
- Both 301 and 302 are HTTP redirect status codes. They tell the browser that The resource you're looking for is available at a different URL. Go there instead.
- 301 = Permanent redirect (the resource has moved permanently).
- 302 = Temporary redirect (the resource has moved temporarily).
- Browsers cache the 301 response and all future visits will directly go to the original URL without visiting our servers which means we will lose analytics.

> Always consider missing resource case and expired resource and present a graceful response to the user.


## 3.Analytics endpoint

- **Endpoint:** `GET short.url/stats/abcd`

**Success Response (200 OK):**

```json
{
  "totalClicks": 200,
  "uniqueClicks": 10,
  "clicksByCountry": { ... },
  "clicksByDevice": { ... },
  "referrers": "Traffic source" 
}
```
- Since we need to store these details we need to track them when a user clicks a link in previous endpoint. But doing all this will increase latency of our request. So, we use async queues to process them later without blocking the user.
