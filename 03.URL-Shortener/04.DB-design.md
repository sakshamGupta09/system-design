# DB Design

## Access Patterns

- Create a short URL.
- Fetch the original URL using short code.
- Fetch all URLs created by a user by ID for analytics.

## SQL vs NoSQL

- First big decision is SQL vs NoSQL. First consider the access patterns.
- **Use SQL** if data is structured, has a well defined schema. ACID transactions: You need reliable transactions and strong consistency. Harder to do horizontal scaling.
- **Use NoSQL** Ff data is nested and flexibility is needed. Easy horizontal scaling from day 1. Fast key value lookups.
- I would consider DynamoDB because URL redirection is a read-heavy workload with a simple key-based access pattern. DynamoDB provides managed horizontal scaling and high read throughput. DynamoDB for main operations and Postgres for analytics and user management.

## Schema

### **URLs Table**

| Field      | Type                 | Description                |
| ---------- | -------------------- | -------------------------- |
| short_code | VARCHAR(10) PK       | Short URL identifier       |
| long_url   | TEXT                 | Original URL               |
| user_id    | BIGINT               | Owner ID (nullable)        |
| created_at | TIMESTAMP            | Creation time              |
| expires_at | TIMESTAMP            | Expiration time (nullable) |

**Index:** `short_code` (unique), `user_id` to query all URLs of a user.

### **URL Analytics Table**

| Field       | Type             | Description                |
| ----------- | ---------------- | -------------------------- |
| short_code  | VARCHAR(10) (FK) | Short URL identifier       |
| clicked_at  | TIMESTAMP        | Click timestamp            |
| ip_address  | VARCHAR(45)      | Visitor IP address         |
| user_agent  | TEXT             | Browser/device information |
| referrer    | TEXT             | Source website             |
| country     | VARCHAR(100)     | Visitor's country          |
| device_type | VARCHAR(50)      | Mobile / Desktop / Tablet  |

**Indexes:**

- `short_code`, `clicked_at`
- For 1 popular URL with 1 million clicks, this table will become huge. We can Store aggregated click statistics.

### **URL Analytics Table**

| Field          | Type             | Description          |
| -------------- | ---------------- | -------------------- |
| short_code     | VARCHAR(10) (PK) | Short URL identifier |
| date           | DATE (PK)        | Analytics date       |
| total_clicks   | BIGINT           | Total clicks         |
| mobile_clicks  | BIGINT           | Mobile clicks        |
| desktop_clicks | BIGINT           | Desktop clicks       |
| tablet_clicks  | BIGINT           | Tablet clicks        |
| updated_at     | TIMESTAMP        | Last updated time    |

**Composite Primary Key:** `(short_code, date)`

**Index:** Compound index `short_code` (unique), `date` for time range queries.
