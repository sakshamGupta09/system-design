# SQL Strengths

1. When the data is highly structured and has a fixed schema.
2. **Strong data consistency (ACID)** Ensures that data remains accurate and consistent, even when multiple operations happen together. Financial systems, Bookings, inventory management.
3. **Handles relationships efficiently** SQL databases are designed to manage relationships between tables using primary and foreign keys.
4. **Strong transaction support** SQL databases support transactions, allowing multiple operations to execute as one logical unit.

SQL databases rely heavily on relationships, JOINs and transactions, which become harder to manage when related data lives on different servers.

## Limitations

1. Difficult to scale horizontally. Scaling SQL databases horizontally is more complex.
2. Schema changes can be difficult. When your application requirements change, you may need to modify the database schema and perform data migration.
3. JOINs can become expensive.
4. Geographical distribution. Imagine your application has users across India and the USA. We create read replica's near to user's locations. Replica's sync takes time. Write still goes to the primary. User's might see a delay while reading.
