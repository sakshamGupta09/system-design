# SQL Strengths

1. **Strong Read Consistency** Whenever you read data, you always get the latest successfully committed data.
2. **Strong transaction support** Allow multiple operations to execute as one logical unit. Ensures DB stays in a valid state when multiple transactions are competing for limited resources simultaneously.
3. **Handles relationships efficiently** Designed to manage relationships between tables using primary, foreign keys and joins.
4. **Analytics Support** Complex ad-hoc queries used to generate reports.

## Examples 

- **Bank transfer**: If ₹1,000 is transferred from A to B, the database ensures that money is deducted from A and added to B. It never updates just one side.
- **Ticket booking**: If hundreds of users have selected one seat, system must book that seat only once.
- **E-commerce inventory**: If thousands of users are trying to buy mac which has only 3 quantity available, we must not oversell.

## Limitations

1. **Difficult to scale horizontally**. Joins and transactions become complex and expensive when data lives on different DB servers.
2. **Rigid schema**. Data we generate has no fixed schema.
3. **Geographical distribution**. Bring data closer to users to reduce latency. But how do these databases stay in sync? Synchronous replication and Asynchronous replication.

## Polyglot persistence

Using multiple types of databases within the same application, choosing each database based on its strengths.
