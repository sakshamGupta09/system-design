# SQL Strengths

1. **Strong data consistency (ACID)** Ensures that data always remains correct and valid, even when multiple users or operations modify it at the same time.
2. **Strong transaction support** SQL databases support transactions, allowing multiple operations to execute as one logical unit.
3. **Handles relationships efficiently** SQL databases are designed to manage relationships between tables using primary, foreign keys and joins.

## Examples 

- **Bank transfer**: If ₹1,000 is transferred from A to B, the database ensures that money is deducted from A and added to B. It never updates just one side.
- **Ticket booking**: If two users try to book the last available seat simultaneously, only one booking succeeds. The same seat cannot be booked twice.
- **E-commerce inventory**: If only one phone is left in stock, two users cannot successfully purchase it simultaneously. The database ensures stock never becomes negative.

## Notes

- SQL is the default choice for Apps that cannot afford to lose or corrupt the data like banks, finance systems, inventories and bookings systems.
- SQL databases rely heavily on relationships, JOINs and transactions, which become harder to manage when related data lives on different servers.

## Limitations

1. **Difficult to scale horizontally**. Scaling SQL databases horizontally is more complex and expensive.
2. **Schema evolution can be difficult**. When your application requirements change, you may need to modify the database schema and perform data migration.
3. **Geographical distribution**. Imagine your application has users across India and the USA. We create read replica's near to user's locations. Writes go the primary and can take time to sync across all read replicas leading to consistency challenges.

## Polyglot persistence

Using multiple types of databases within the same application, choosing each database based on its strengths.
