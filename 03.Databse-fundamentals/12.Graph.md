# Graph Databases

A DB which not only stores data but also represents relationships. Instead of organising data in tables, it represents data using three components:

- **Nodes:** Represent entities (people, products, places, etc.).
- **Edges:** Represent relationships between entities. How the nodes are connected.
- **Properties:** Store additional information about nodes and relationships.

## How It Works

Imagine a social media application with three users:

```text
Alice ──FOLLOWS──> Bob ──FOLLOWS──> Charlie
```

Here:
- Alice, Bob and Charlie are **nodes**.
- FOLLOWS represents the **relationship (edge)** between users.
- Each user can have properties like name, age and location.

Now, suppose we want to find out who Alice's friends follow.

The database can traverse the relationships:

1. Find Alice.
2. Follow Alice's outgoing relationship to Bob.
3. Follow Bob's outgoing relationship to Charlie.

This is called **relationship traversal**. Graph databases make these relationship-based queries natural and efficient.

## Real-World Use Cases

| Use case | How graph databases help |
|---|---|
| Social networks | Find friends, followers and mutual connections. |
| Recommendation engines | Recommend products based on users with similar interests and purchases. |
| Fraud detection | Identify suspicious connections between accounts, devices and transactions. |
| Knowledge graphs | Connect people, organisations, concepts and information. |

**Popular graph database:** Neo4j, Amazon Neptune
