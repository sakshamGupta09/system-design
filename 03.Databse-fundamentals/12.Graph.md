# Graph Databases

## 1. Introduction

A **Graph Database** is a database designed to store and manage data based on relationships between entities.

Instead of organising data in tables, it represents data using three components:

- **Nodes:** Represent entities (people, products, places, etc.).
- **Edges:** Represent relationships between entities.
- **Properties:** Store additional information about nodes and relationships.

**Example:** A social media application where users follow, connect with and interact with other users.

## 2. How It Works

Imagine a social media application with three users:

```text
Alice ──FOLLOWS──> Bob ──FOLLOWS──> Charlie
```

Here:
- Alice, Bob and Charlie are **nodes**.
- FOLLOWS represents the **relationship (edge)** between users.
- Each user can have properties like name, age and location.

Now, suppose we want to find out who Alice's friends follow.

The database can traverse the relationships:

1. Find Alice.
2. Follow Alice's outgoing relationship to Bob.
3. Follow Bob's outgoing relationship to Charlie.

This is called **relationship traversal**.

Graph databases make these relationship-based queries natural and efficient.

## 3. How Does It Store Data?

Graph databases organise data using three components:

| Component | What it stores | Example |
|---|---|---|
| Node | Entities | Alice, Bob |
| Edge | Relationships | Alice follows Bob |
| Properties | Additional details | Name, age, since |

Think of it this way:
- Nodes represent things.
- Edges represent connections between things.
- Properties describe those things and connections.

## 4. Key Strengths

1. **Excellent for relationship-heavy data:** Makes it easy to represent complex connections.
2. **Fast relationship traversal:** Efficiently explores connections across multiple entities.
3. **Flexible data model:** New types of relationships and entities can be introduced easily.
4. **Intuitive querying:** Queries focus on relationships and patterns rather than complex joins.

## 5. Real-World Use Cases

| Use case | How graph databases help |
|---|---|
| Social networks | Find friends, followers and mutual connections. |
| Recommendation engines | Recommend products based on users with similar interests and purchases. |
| Fraud detection | Identify suspicious connections between accounts, devices and transactions. |
| Knowledge graphs | Connect people, organisations, concepts and information. |
| Network management | Understand connections between servers, devices and services. |

## 6. When Should You Use Graph Databases?

Use a graph database when:

- Relationships between entities are as important as the entities themselves.
- Your application frequently needs to traverse multiple levels of relationships.
- Queries involve complex connections that would otherwise require multiple expensive joins.

**Example:**

In a fraud detection system, you want to identify whether multiple bank accounts are connected through the same device, phone number or address.

A graph database makes exploring these connections much more natural.

**Remember:** Graph databases are designed to make storing, querying and exploring relationships between data efficient.
