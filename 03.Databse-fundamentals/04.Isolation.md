# Isolation

When and how changes made by concurrently executing transactions become visible to one another.

Problems Isolation Prevents -

## A. Dirty Read

Reading another transaction's uncommitted changes.

Example:
1. Transaction A changes balance from ₹1,000 to ₹500.
2. Transaction B reads the new balance (₹500).
3. Transaction A rolls back.
4. Transaction B has read a value that was never actually committed.

## B. Non-Repeatable Read

Reading the same row twice and getting different values because another transaction modified it.

Example:
1. Transaction A reads balance = ₹1,000.
2. Transaction B updates balance to ₹500 and commits.
3. Transaction A reads the same account again = ₹500.

## C. Phantom Read

Running the same query twice and getting different sets of rows because another transaction inserted or deleted matching rows

Example:
Transaction A executes:

```sql
SELECT * FROM employees WHERE salary > 50000;
```

- It gets 5 employees.
- Meanwhile, Transaction B inserts a new employee with a salary of ₹70,000 and commits.
- Transaction A runs the same query again and gets 6 employees.

## D. Lost Update

One transaction overwrites another transaction's update

Example
- Imagine an online store has 10 units of a product. Two customers place orders simultaneously:
- Transaction A: Reads inventory = 10. Transaction B: Reads inventory = 10.
- Transaction A: Sells 3 units and updates inventory to 7.
- Transaction B: Sells 4 units and updates inventory to 6.
- The correct inventory should be 3, but it ends up being 6.

##  Solution: Isolation Levels

1. **Read Uncommitted:** You can read uncommitted changes from other ransactions. Weakest isolation.
2. **Read Committed:** Postgres Default. You only read committed data. However, data can change between two reads.
3. **Repeatable Read:** Once you read a row, its value remains consistent within your transaction.
4. **Serializable:** Transactions behave as if they executed one after another. Strongest isolation.

| Isolation Level | Dirty Read | Non-Repeatable Read | Phantom Read |
|---|---|---|---|
| Read Uncommitted | Yes | Yes | Yes |
| Read Committed | No | Yes | Yes |
| Repeatable Read | No | No | Possible* |
| Serializable | No | No | No |
