# Durability

- Once a transaction is committed, it survives permanently no matter what happens to the system.
- The power outages, the hardware failures, and even the complete data center disasters.


## How does the database achieve this?

Databases primarily use Write-Ahead Logging (WAL). Think of WAL as a safety diary that records every change before applying it to the actual database files.

1. Record the change: Before modifying the actual database data, the database writes the intended change into a transaction log (WAL).
2. Persist the log: The database flushes the log to durable storage (disk/SSD).
3. Commit: Once the log is safely persisted, the database confirms that the transaction is committed.
4. Apply changes: The database can write the actual changes to its data files later.

## What happens if the database crashes?

Suppose the database crashes after confirming the transaction but before updating the actual data files.
- On restart, the database examines its WAL.
- It identifies committed transactions.
- It replays the necessary changes to restore the database to the correct state.
Your committed transaction is not lost!
