# Key-Value Stores

Stores data as **key-value pairs**, similar to a dictionary or a HashMap. Fastest databases.

- **Key:** A unique identifier used to find data.
- **Value:** The data associated with that key.

Example:

```json
{
  "user:101": {
    "name": "John",
    "age": 28
  },
  "user:102": {
    "name": "Alice",
    "age": 25
  }
}
```

To retrieve John's details, the application provides `user:101` and gets the associated value rather than using any complex queries.

## Key Strengths

1. **Extremely fast lookups:** Data can be retrieved directly using its key, making reads very fast.
2. **High scalability:** Data can be distributed across multiple servers based on keys, allowing the database to handle massive amounts of data and traffic.
3. **High throughput:** Designed to handle a large number of read and write operations efficiently.
4. **Simplicity** No schemas, tables or joins. Just simple key value pairs.

## Real-World Use Cases

| Use Case | Example |
|---|---|
| Caching | Store frequently accessed user profiles or API responses. |
| Session management | Store user login sessions using session IDs as keys. |
| Shopping carts | Store each user's cart using their user ID as the key. |
| User preferences | Store settings such as theme and language using user ID as the key. |
| Rate limiting | Track API request counts using user IDs or API keys. |

## Popular Databases

- **Redis:** Commonly used for caching, session management, and rate limiting. Stores everything in RAM and hence is super fast. Also, supports storing different data structures as value. RAM is very expensive compared to SSD.
- **Amazon DynamoDB:** Used for highly scalable applications that need fast key-based access. Not limited by RAM.


## Cache Aside Pattern

- Check if data is available in Redis first.
- If yes, serve it in microseconds from Redis (Cache hit).
- If not, query PostgresSQL and store the data in Redis again. (Cache miss)
- Popular celebrities profiles which are viewed millions of times always stay in the cache.
