# MVCC

## Problem

Imagine a social media application where a post has 100 likes.

Two users access the same post simultaneously:
- User A is reading the post and its like count.
- User B likes the post, increasing the count to 101.
Now imagine User A's database query takes 5 seconds to complete. What should happen? Should User A's read operation wait until User B finishes updating the database? Or should User B's update wait until User A finishes reading?

Neither is ideal. We want both operations to happen simultaneously without interfering with each other. This is where MVCC comes in.

## MVCC

- MVCC (Multi-Version Concurrency Control) is a technique used by SQL databases to allow multiple transactions to access the same data simultaneously without unnecessarily blocking each other.
- Instead of overwriting existing data immediately, the database maintains multiple versions of a row.

## How it works

| Post ID   | Likes   |
| --------  | ------- |
| 101       | 100     |

- Imagine a database has this row in initial state. Now two transactions happen simultaneously.
- Transaction A — Reading. User A starts reading the post. Sees the version one 100 Likes.
- Transaction B — Updating User B likes the post. The database creates a new version instead of immediately destroying the old one.
- Version 1 Old Likes: 100 and Version 2 new Likes: 101
- User A continues reading the old version (100). User B successfully updates the new version (101).
- New transactions can see the updated version, depending on their isolation level.
- User A doesn't need to wait for User B's update, and User B doesn't need to wait for User A's read to finish.

## 4. Why do we need MVCC?
Without MVCC, databases often rely more heavily on locking.

For example:
- A transaction reading a row might hold a lock.
- Another transaction trying to update that row might have to wait.
- This increases waiting time and reduces concurrency.
With MVCC:
- Readers can access an older version.
- Writers can create a newer version.
- Readers and writers can work concurrently in many situations.
This improves database performance and concurrency.

5. Does MVCC mean there are no locks?
No! This is important.

MVCC reduces the need for read-write blocking, but databases still use locks for operations such as conflicting writes.

For example, if two users simultaneously try to update the same row, the database must coordinate those updates to prevent lost updates.

Remember this
MVCC = Multiple Versions of the Same Data.

Instead of making readers wait for writers (or vice versa), the database allows readers to access an appropriate existing version while writers create newer versions.

One-line intuition: Readers read snapshots; writers create new versions. Both can work concurrently.
