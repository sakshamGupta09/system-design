# Problem

What happens when two users access the same data simultaneously? Imagine a post has 100 likes in your database. Two users access it simultaneously.

- User A: Reads the post and takes 5 seconds to complete the query.
- User B: Likes the post, updating the count from 100 to 101.

Should User A and User B block each other? Ideally, NO! Both operations should happen without unnecessarily waiting for each other.

## MVCC (Multi-Version Concurrency Control) 

Instead of overwriting existing data immediately, the database maintains multiple versions of the same data (a row).

## How it works

- Initially, the database has Version 1: likes = 100.
- User A starts reading. The database gives User A access to Version 1.
- User B updates the likes count to 101. The database creates Version 2: likes = 101.
- User A continues reading Version 1 and sees 100 likes.
- New readers can see Version 2 and get 101 likes.
- Both operations proceed without blocking each other.

## 4. Why do we need MVCC?
Without MVCC, databases often rely more heavily on locking.

For example:
- A transaction reading a row might hold a lock.
- Another transaction trying to update that row might have to wait.
- This increases waiting time and reduces concurrency.

With MVCC:
- Readers get a consistent snapshot of the data.
- Writers create new versions instead of making readers wait.
- Old versions are cleaned up when they are no longer needed.

This improves database performance and concurrency as reads and writes generally don't block each other.
