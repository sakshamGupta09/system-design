## MVCC (Multi-Version Concurrency Control) 

- How does a DB internally implements isolation levels?
- One way is to use locks. One transaction will acquire a lock and complete it's operations while others will wait.
- This creates unnecessary waiting, especially when many transactions are running simultaneously.
- MVCC solves this by maintaining multiple versions of the same data instead of immediately overwriting the existing data.
- This allows readers and writers to work concurrently in many situations.

## How it works

- Initially, the database has Version 1: likes = 100.
- User A starts reading. The database gives User A access to Version 1.
- User B updates the likes count to 101. The database creates Version 2: likes = 101.
- User A continues reading Version 1 and sees 100 likes.
- New readers can see Version 2 and get 101 likes.
- Both operations proceed without blocking each other.

## With MVCC

- Readers get a consistent snapshot of the data.
- Writers create new versions instead of making readers wait.
- Old versions are cleaned up when they are no longer needed.

This improves database performance and concurrency as reads and writes generally don't block each other.
