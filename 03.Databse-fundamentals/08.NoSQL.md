# NoSQL Strengths

1. **Horizontal Scaling** Distributes data across multiple servers. Helps handle increasing traffic and massive amounts of data.
2. **High Availability** Data is replicated across multiple servers. If one server fails, other servers can continue serving requests.
3. **Flexible Schema** Nature of data is such that different records can have different attributes.
4. **High Performance** Many NoSQL databases are optimized for specific query patterns. They can provide very fast reads and writes at scale.
5. **Eventual Consistency** Data may not be immediately consistent across all servers. Eventually, all replicas converge to the latest value.

## BASE Properties

Many distributed NoSQL databases follow the BASE properties.

- **Basically Available:** The system continues serving requests even when some servers fail.
- **Soft State:** Data can temporarily differ across servers.
- **Eventually Consistent:** All servers eventually converge to the same state.

## 3. Limitations of NoSQL

**1. Limited Joins**
- Complex queries involving multiple related datasets can be difficult.
- You may need multiple queries and combine results in application code.

**2. Data Duplication**
- Data may need to be duplicated (denormalization) to make reads faster.
- Updating duplicated data consistently becomes more difficult.

**3. Data Consistency**
- Some databases may allow temporarily stale data due to eventual consistency.
- This may not be suitable for applications requiring immediate consistency.

**4. Schema Management**
- Flexible schemas require application-level validation and discipline.
- Incorrect or inconsistent data structures can enter the database if not properly validated.

**5. Operational Complexity**
- Managing distributed databases can require expertise in replication, partitioning, and consistency.
