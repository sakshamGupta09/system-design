## Key Strengths of NoSQL

**1. Horizontal Scalability**
- Distributes data across multiple servers.
- Instead of upgrading one powerful server (vertical scaling), we add more servers (horizontal scaling).
- Helps handle increasing traffic and massive amounts of data.

*Example:* A social media application can distribute user data across multiple servers to handle millions of users.

**2. High Availability**
- Data is replicated across multiple servers.
- If one server fails, other servers can continue serving requests.
- Helps build fault-tolerant systems.

*Example:* If one server storing Instagram posts goes down, another replica can continue serving those posts.

**3. Flexible Schema**
- No need to define a rigid schema upfront in many NoSQL databases.
- Different records can have different fields.
- Makes it easier to handle evolving data structures.

*Example:* In a product catalog, a mobile phone may have RAM and storage fields, while a T-shirt may have size and color fields.

**4. High Performance**
- Many NoSQL databases are optimized for specific query patterns.
- They can provide very fast reads and writes at scale.

*Example:* Redis can retrieve cached user session data using a key in very little time.

**5. Eventual Consistency**
- Data may not be immediately consistent across all servers.
- Updates propagate over time.
- Eventually, all replicas converge to the latest value.

*Example:* After changing your profile picture, some users might temporarily see the old picture until the update reaches all replicas.

*Note: Not all NoSQL databases use eventual consistency. Some support strong consistency too.*

## 2. BASE Properties

Many distributed NoSQL databases follow the BASE approach.

BASE stands for:

- **Basically Available:** The system continues serving requests even when some servers fail.
- **Soft State:** Data across replicas may change as updates propagate, even without a new user request.
- **Eventually Consistent:** All replicas eventually converge to the same data.

*Example:* You update your profile picture. Some servers may temporarily serve the old picture, but eventually all servers show the updated picture.

## 3. Limitations of NoSQL

**1. Limited Joins**
- Complex queries involving multiple related datasets can be difficult.
- You may need multiple queries and combine results in application code.

**2. Data Duplication**
- Data may need to be duplicated (denormalization) to make reads faster.
- Updating duplicated data consistently becomes more difficult.

**3. Data Consistency**
- Some databases may allow temporarily stale data due to eventual consistency.
- This may not be suitable for applications requiring immediate consistency.

**4. Schema Management**
- Flexible schemas require application-level validation and discipline.
- Incorrect or inconsistent data structures can enter the database if not properly validated.

**5. Operational Complexity**
- Managing distributed databases can require expertise in replication, partitioning, and consistency.

## 4. SQL vs NoSQL – When to Use?

| SQL | NoSQL |
|---|---|
| Strong relational requirements | Flexible data models |
| Complex joins and queries | Predictable query patterns |
| ACID transactions are important | Massive horizontal scalability |
| Banking, payments, orders | Caching, logs, social feeds |

**Important:** NoSQL is not necessarily better than SQL. Both solve different problems.

## 5. Polyglot Persistence

**Meaning:** Using multiple types of databases within the same application, choosing each database based on its strengths.

*Example: An e-commerce application*

- PostgreSQL → User accounts and payments.
- MongoDB → Product catalog.
- Redis → User sessions and caching.
- Graph database → Product recommendations.

This avoids forcing one database to handle every type of workload.

## Remember

- NoSQL offers flexible schemas and easier horizontal scaling.
- High availability is achieved through replication.
- BASE describes a common approach to availability and eventual consistency.
- NoSQL trades some relational capabilities for scalability and flexibility.
- SQL and NoSQL complement each other; choose based on workload.
