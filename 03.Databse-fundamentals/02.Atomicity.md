# Atomicity

- All or nothing rule. All operations in a transaction succeed completely, or all operations are rolled back.
- No partial updates are allowed.
- If any single operation fails, the entire transaction is rolled back.

### Example

Imagine you're transferring ₹1,000 from Account A to Account B. Two operations are required:

1. Deduct ₹1,000 from Account A.
2. Add ₹1,000 to Account B.

Suppose the first operation succeeds, but the second operation fails. Without atomicity, Account A loses ₹1,000. Account B receives nothing and ₹1,000 effectively disappears!

### Transaction Log or Write Ahead Log

- Before the database modifies any of the actual data on the disk, it first writes all the intended changes to this special log.
- Then, if something goes wrong during the execution, it can use the log to undo any partial changes that were made, which ensures the database returns to exactly the state it was in before the transaction started.
