# Consistency

- A transaction must take DB from one valid state to another.
- The data after transaction completion follows all the rules and constraints defined like Primary key, Foreign Key, Unique, Not Null, Check.
- If any single rule or constraint fails during the transaction, entire transaction is rolled back.

### Example

- An e-commerce system has a business rule that the inventory levels cannot go negative.
- So if an order comes in that would push the inventory below zero, the database will reject the entire transaction rather than allowing that invalid data to exist.
