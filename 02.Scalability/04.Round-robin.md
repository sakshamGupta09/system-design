# Round Robin

- Distribute requests equally among servers. Each server handles almost equal number of requests.

```text
Requests: R1  R2  R3  R4  R5  R6
             |
        Load Balancer
         /    |    \
       S1     S2     S3

Distribution:
S1 → R1, R4
S2 → R2, R5
S3 → R3, R6
```

- The pattern repeats: `S1 → S2 → S3 → S1 → ...`

### Pros
- Simple, fast and predictable.
- Works well when servers have similar capacities and requests have similar processing time.

### Cons
- **Server Capacity** Treats powerful and weak servers equally.
- **Server Load** Ignores current load on server. A server handling heavy traffic can receive additional requests.
- **Request Processing Time** Treats a simple and complex request equal.

## Weighted Round Robin (WRR)

- Considers server's capacity. A powerful server will handle more number of requests.
- Assigns each server a weight based on it's capacity.

## Pros
- Supports servers with different capacities.
