# Least Connections

- Send the next request to the server currently handling the fewest active connections.

## Real-world analogy

Imagine three cashiers at a supermarket.
- Cashier A is serving 5 customers.
- Cashier B is serving 2 customers.
- Cashier C is serving 4 customers.

A new customer arrives and we send them to Cashier B because they have the shortest queue.

### Benifits

- Considers current load on server.
- Handles long-running requests better. Servers handling long-lived connections receive fewer new requests, allowing other servers to take more traffic.
- Adapts dynamically: As connections open and close, the load balancer adjusts its decisions automatically.

## Limitations

- Additional tracking overhead:The load balancer needs to track active connections for every server and update this information continuously.
- Doesn't consider server capacity: A powerful server and a weaker server may have the same number of active connections but very different processing capabilities.
- Connections don't represent actual workload: Active connections are only an approximation of actual server load. Two connections might have very different processing requirements. One could be CPU-intensive, while another might be almost idle.
