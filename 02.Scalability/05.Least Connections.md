# Least Connections

- Send the next request to the server currently handling the least active connections.
- Instead of distributing requests equally, distribute them based on how busy each server currently is.

## Real-world analogy

Imagine three cashiers at a supermarket.
- Cashier A is serving 5 customers.
- Cashier B is serving 2 customers.
- Cashier C is serving 4 customers.

A new customer arrives and we send them to Cashier B because they have the shortest queue.

### When to use

- You want to avoid sending more work to already busy servers.

## Limitations

- Connection count doesn't always represent actual server load: A server handling 5 CPU-intensive requests might be busier than one handling 10 lightweight requests.
- Doesn't consider server capacity: If servers have different processing capabilities, simply counting connections may not distribute work optimally.
- Requires connection tracking: The load balancer must track active connections and update counts as connections open and close.
