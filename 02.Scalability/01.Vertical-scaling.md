# Vertical Scaling

- A server has a fixed capacity to handle a certain QPS. As traffic grows, it will become overloaded leading to high response time or requests timing out.
- Increase the resources of an existing server to handle more requests.

You upgrade the server by adding:
- More CPU → Process more operations.
- More RAM → Handle more data in memory.
- Faster storage → Read and write data faster.

**Example:** Upgrading a server from 4 CPU cores and 8 GB RAM to 16 CPU cores and 32 GB RAM.

##  When to Choose

- Application has low to moderate traffic that can be handled by a single server.
- Application is difficult to distribute.
- Vertical scaling is particularly common for databases.
- Keep infrastructure simple.

## When NOT to Choose

- **You have reached the server's maximum capacity:** Hardware upgrades have limits.
- **You need high availability:** One server remains a single point of failure.
- Geographical distribution

## Key Limitations

- **Hardware ceiling:** You cannot upgrade a server indefinitely.
- **Cost:** Powerful servers can become expensive.
- **Single point of failure:** If the server goes down, the application may go down.
- **Downtime risk:** Some upgrades may require restarting the server.
- **Geographical distribution:** A single server may cause high latency for users located far away.
