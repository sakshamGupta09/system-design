# Vertical Scaling/ Scaling Up

- Goal is to handle more load on our system.
- Increasing the resources of an existing server to handle more workload. A more powerful server can process more requests and handle a larger workload.

You upgrade the server by adding:
- More CPU → Process more operations.
- More RAM → Handle more data in memory.
- Faster storage → Read and write data faster.

**Example:** Upgrading a server from 4 CPU cores and 8 GB RAM to 16 CPU cores and 32 GB RAM.

## Problem

As an application grows, more users send requests to the server. A server with limited resources may experience:
- High CPU usage.
- Insufficient memory.
- Slower response times.
- Requests timing out.

**Example:** An e-commerce website initially handles 100 requests per second. As traffic grows to 1,000 requests per second, its server becomes overloaded.

## Analogy

- When a family grows from 2 to 6 members, we get a bigger car instead of multiple smaller ones.

##  When to Choose Vertical Scaling?

- **Early-stage applications:** Simple architecture and low traffic.
- **Simplicity matters:** When you want to avoid managing multiple servers.
- **Quick performance improvements:** When the server is running out of CPU or RAM.
- **Databases:** When a database needs more memory or processing power. Distributed databases are complex.

## When NOT to Choose Vertical Scaling?

- **You have reached the server's maximum capacity:** Hardware upgrades have limits.
- **You need high availability:** One server remains a single point of failure.

## Key Limitations

- **Hardware ceiling:** You cannot upgrade a server indefinitely.
- **Cost:** Powerful servers can become expensive.
- **Single point of failure:** If the server goes down, the application may go down.
- **Downtime risk:** Some upgrades may require restarting the server.
