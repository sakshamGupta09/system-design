# Vertical Scaling

## 1. What is Vertical Scaling?

**Vertical scaling means increasing the power of an existing server** to handle more workload.

You can upgrade a server by adding more:
- **CPU:** To process more requests.
- **RAM:** To handle more data and concurrent operations.
- **Storage:** To store more data.

**Example:**

- **Before:** A server with 4 CPU cores and 8 GB RAM.
- **After:** The same server upgraded to 16 CPU cores and 32 GB RAM.

The upgraded server can potentially handle more requests per second.

**Key idea:** Instead of adding more servers, you make the existing server more powerful.

## 2. Why Do We Use Vertical Scaling?

Imagine you're running an e-commerce website on one server.

Initially, 100 users visit your website at a time, and everything works smoothly. As your business grows, thousands of users arrive, and the server becomes slow.

You discover that the server's CPU is overloaded and it doesn't have enough RAM.

**Solution:** Upgrade the server with more CPU power and RAM so it can handle the increased workload.

Vertical scaling helps you:
- Handle more requests using the same server.
- Improve performance when CPU or memory is the bottleneck.
- Keep the architecture simple without managing multiple application servers.

## 3. When Should You Use Vertical Scaling?

- **Small or growing applications:** One powerful server is sufficient.
- **Quick performance improvements:** Upgrading resources can be simpler than redesigning the system.
- **Database performance:** Databases may benefit from additional RAM or CPU.
- **Workloads that are difficult to distribute:** Some applications are easier to run on one powerful machine.

**Example:** Your PostgreSQL database frequently reads data from disk because it doesn't have enough RAM to cache frequently accessed records. Adding RAM may significantly improve performance.

## 4. When Should You Avoid Vertical Scaling?

### A. When You Reach the Server's Maximum Capacity

Every server has a limit. You cannot keep adding CPU and RAM forever.

**Example:** Your server already has 64 CPU cores and 256 GB RAM, but traffic continues to grow. You may need to add more servers.

### B. When You Need High Availability

Vertical scaling does not eliminate the single point of failure.

**Example:** If your entire application runs on one server and that server crashes, your website goes down—even if it is extremely powerful.

### C. When Traffic Fluctuates Significantly

Upgrading to a large server just to handle occasional traffic spikes can be expensive.

**Example:** During a Black Friday sale, traffic increases tenfold for a few hours. Adding multiple application servers temporarily may be more cost-effective than permanently upgrading to a huge server.

### D. When Your Workload Can Be Distributed

If requests can be handled independently by multiple servers, distributing the workload may allow you to scale further.

**Example:** An application receives millions of requests. Instead of making one server increasingly powerful, you can distribute requests across multiple servers using a load balancer.

## 5. Vertical Scaling vs. Horizontal Scaling

| Vertical Scaling | Horizontal Scaling |
|---|---|
| **Scale up** | **Scale out** |
| Make one server more powerful. | Add more servers. |
| Simple to implement and manage. | Requires coordination between servers. |
| Limited by the maximum capacity of one machine. | Can support much greater capacity by adding servers. |
| A single server can remain a point of failure. | Multiple servers can improve availability when designed with redundancy. |

## Key Takeaway

- **Vertical scaling = Scale up:** Make one server more powerful.
- **Horizontal scaling = Scale out:** Add more servers.

Start with vertical scaling when simplicity and the capacity of one machine are sufficient. Consider horizontal scaling when you need greater capacity, better availability, or more flexible handling of traffic spikes.
