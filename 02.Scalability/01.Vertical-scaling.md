# Vertical Scaling (Scaling Up)

## 1. What Is Vertical Scaling?

**Why do we need it?**

As users and requests increase, a server may run out of CPU, RAM, or other resources, causing slow responses and timeouts.

**What is the solution?**

Vertical scaling means **upgrading an existing server with more powerful hardware** instead of adding more servers.

For example:

- **Before:** 2 CPU cores and 8 GB RAM — handles 1,000 concurrent users comfortably.
- **Problem:** Traffic increases, and the server struggles with 2,000 users.
- **After:** Upgrade to 16 CPU cores and 64 GB RAM — the same application can handle more traffic.

The exact capacity depends on the application and workload, but the idea is simple: **one bigger server instead of multiple smaller servers.**

## 2. How Does the Cost Scale?

A more powerful server can handle more work, but its cost doesn't always increase proportionally.

Illustrative monthly cloud-server costs:

| Server configuration | Monthly cost |
|---|---:|
| 1 vCPU, 1 GB RAM | $8 |
| 2 vCPUs, 8 GB RAM | $67 |
| 96 vCPUs, 384 GB RAM | $4,600 |
| 128 CPUs, 3,904 GB RAM | $26,688 |

**Key takeaway:** High-end servers can become disproportionately expensive because powerful hardware is specialized and costly.

Vertical scaling is affordable initially, but upgrading further can become expensive.

## 3. Why Does Vertical Scaling Have Limits?

There are three important limitations.

### A. Hardware has a physical limit

You cannot keep adding CPU cores and RAM to a single machine indefinitely. Eventually, you reach the limits of available hardware.

Moore's Law describes Gordon Moore's 1965 observation that transistor counts on integrated circuits historically doubled roughly every two years. However, this is an observation about historical hardware progress, not a strict law that determines a server's maximum capacity.

### B. Some workloads need too much processing power

Imagine a social network processing **4 million likes per second**.

Each like requires 1 millisecond of CPU processing.

- Required CPU time: 4,000 seconds of processing per second.
- At an idealized rate of one task per core, that requires roughly 4,000 continuously busy CPU cores.
- This excludes database work, notifications, timeline updates, and other overhead.

A single server cannot handle this workload within the assumed processing model. You would need to distribute the work across multiple machines.

### C. A single server is a single point of failure

If the server crashes, the entire application running on it may become unavailable.

Adding more power does not solve this problem. Multiple servers can improve availability by allowing other servers to continue serving requests when one fails.

## 4. When Does Vertical Scaling Make Sense?

Vertical scaling is often a good starting point because it is simple and avoids unnecessary distributed-system complexity.

### A. Small and medium-sized applications

For websites and applications with moderate traffic, one powerful server may be sufficient.

You get:
- Simpler deployment and operations.
- No need to distribute application processing across multiple servers.
- Immediate performance improvements without necessarily changing the code.

**Example:** Stack Overflow has historically served substantial traffic with a relatively small number of powerful web servers, combined with extensive caching and code and database-query optimization.

### B. Databases

Databases often benefit significantly from vertical scaling because more RAM can keep frequently accessed data in memory, while additional CPU capacity can help process queries.

For example, a powerful database server may handle millions of queries per day without requiring a distributed database.

As traffic grows, you can first optimize queries, add indexes, use caching, and upgrade hardware. Consider sharding when one database can no longer meet your capacity or performance requirements.

**Why not shard immediately?**

Sharding distributes data across multiple database servers, introducing additional complexity around data distribution, queries, consistency, and operations.

### C. Applications that are difficult to distribute

Some legacy enterprise applications, scientific workloads, and financial systems are designed to run on a single machine.

Distributing these applications may require expensive architectural changes or significant code rewrites.

In such cases, vertical scaling can be a practical solution for extending their capacity.

## 5. Advantages of Vertical Scaling

- **Simple:** Easier to deploy, monitor, debug, and maintain.
- **Fewer code changes:** Upgrading hardware often requires no application changes.
- **Lower complexity:** No need to distribute application work across multiple servers.
- **Low internal network overhead:** Components on the same machine avoid some network communication.
- **Simpler data management:** A single database can simplify backups and recovery.
- **Quick performance improvement:** More CPU or RAM can resolve resource bottlenecks.

## 6. Disadvantages of Vertical Scaling

- **Hardware limits:** A single machine cannot grow indefinitely.
- **Increasing cost:** High-end servers become expensive.
- **Single point of failure:** One server failure can take down the application.
- **Upgrade downtime:** Some upgrades require restarting or migrating the server.
- **Limited geographic distribution:** One server cannot independently serve users from multiple regions with low latency.
- **Hardware dependency:** Specialized configurations may limit your choice of cloud provider or infrastructure.

## 7. When Should You Move to Horizontal Scaling?

Horizontal scaling means **adding more servers instead of making one server bigger.**

Consider it when:

- Upgrading one server becomes more expensive than adding multiple servers.
- You approach the maximum capacity of a single machine.
- You need better fault tolerance and availability.
- You need to serve users from multiple geographical regions.
- Server upgrade downtime becomes unacceptable.
- Your workload can be divided across multiple machines to handle more traffic.

You do not need to wait until vertical scaling completely fails. You can introduce horizontal scaling gradually, while continuing to use powerful individual servers for components such as databases.

## 8. Common Misconception: Is There a Fixed User Limit?

There is no universal limit such as 100,000 or 1 million users at which vertical scaling stops working.

The limit depends on:
- Requests per second.
- CPU and memory requirements per request.
- Database workload.
- Caching efficiency.
- Application architecture.
- Available hardware and budget.

A well-optimized application might support millions of users with a small number of servers, while a poorly optimized application might struggle with far fewer.

## Quick Revision

| Vertical scaling | Key idea |
|---|---|
| Meaning | Make an existing server more powerful |
| Also called | Scaling up |
| Best for | Small to medium workloads, databases, and hard-to-distribute applications |
| Main advantages | Simplicity, lower operational complexity, quick performance gains |
| Main disadvantages | Hardware limits, rising costs, single point of failure |
| When to scale horizontally | When capacity, cost, availability, or geographic requirements demand multiple servers |

**Remember:** Start with vertical scaling when simplicity is valuable. Move toward horizontal scaling when one machine is no longer sufficient or when availability and distribution become important.
