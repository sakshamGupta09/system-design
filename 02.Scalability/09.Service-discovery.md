# Problem

- Or application has muliple services which need to communicate with each other.
- How does service A knows where service B is running?
- We can hardcode an IP address of a service but 

Now consider these situations:

1. What if its IP address changes?
2. A service can have multiple instances to handle more traffic.
3. New instances are added and old instances are removed as traffic changes.

Hardcoding IP addresses becomes difficult to maintain.

## Service Discovery Pattern

- Instead of hardcoding IP addresses, services dynamically discover where other services are running.

```text
http://payment-service:8080
```


## Service Registry

```text
Payment Service      192.168.1.10:8080
                     192.168.1.11:8080
                     192.168.1.12:8080

User Service         192.168.1.20:8080
                     192.168.1.21:8080
                     192.168.1.22:8080

Order Service        192.168.1.30:8080
                     192.168.1.31:8080
```

- It maintains information about all available service instances.
- Whenever a service starts, it registers its location in the registry.
- When it stops or becomes unhealthy, its entry can be removed.

## Client-Side Service Discovery

The client service is responsible for finding and selecting an available service instance.

- Order Service asks the Service Registry for Payment Service instances.
- Registry returns three available instances.
- Order Service selects one instance using a load-balancing algorithm.
- Order Service directly communicates with that instance.

The client handles service discovery and load balancing.

## Server-Side Service Discovery

The client doesn't need to know the actual IP addresses of service instances. Instead, it sends the request to a Load Balancer. The Load Balancer finds an available instance and forwards the request.

- Order Service sends a request to the Payment Service Load Balancer.
- Load Balancer identifies an available Payment Service instance.
- It forwards the request to that instance.
- Payment Service processes the request.

Key point: The Load Balancer handles service discovery and routes requests to available instances.
