# IP Hash

- Use a client's IP address to decide which server should handle their requests.
- It applies a hash function to the client's IP address and uses the result to select a backend server.
- Requests from the same IP address generally go to the same server.

Mental model: Think of IP Hash as assigning each customer's IP address to a particular checkout counter. Whenever that customer returns, they are directed to the same counter.

## Why is this useful?

Session persistence (sticky sessions).

Imagine:
1. A user logs into an e-commerce application.
2. Server A handles the login and stores the user's session in its local memory.
3. The user adds products to their shopping cart.
4. The next request also reaches Server A because of IP Hash.
This allows Server A to access the user's existing session without requiring the user to log in again.

## Pros

- Session persistence: Requests from the same IP are consistently routed to the same server.
- Cache locality: Repeated requests from the same client can benefit from data cached on the same server.

## Cons

- **Uneven load distribution** Multiple users behind the same corporate NAT share one public IP. They all get routed to the same backend server. One server can become overloaded while others remain idle.
- **Changing client IPs** Mobile users frequently switch between Wi-Fi and cellular networks. Their IP address changes, potentially routing them to another server. Their locally stored session may no longer be accessible.
- Server failure: If the assigned server goes down, requests need to be redirected, potentially disrupting existing sessions.
- Changing server pool: Adding or removing servers can change hash mappings and cause clients to be routed to different servers.
