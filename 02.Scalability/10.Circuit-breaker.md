# Circuit Breakers and Resilience in System Design

## 1. What Problem Are We Solving?

Imagine an e-commerce application where:

- Order Service calls Payment Service.
- Payment Service calls an external Payment Processor.

Now, suppose the Payment Processor becomes slow and takes 30 seconds to respond instead of 1 second.

**Without protection:**

1. Payment Service keeps waiting for responses.
2. Its threads and connections get occupied.
3. Requests start piling up.
4. Payment Service runs out of resources and may crash.
5. Other services depending on it may also fail.

This is called a **Cascading Failure** — one service failure triggers a chain reaction that brings down other services.

## 2. What is Resilience?

**Resilience is the ability of a system to handle failures and continue working without bringing down the entire application.**

For example:
- If recommendations fail, users should still be able to browse products.
- If reviews fail, users should still see product details.
- If payments fail, the system should handle the failure gracefully.

**Goal:** Keep the core functionality working even when some components fail.

## 3. What is a Circuit Breaker?

A **Circuit Breaker is a design pattern that temporarily stops requests to an unhealthy service to prevent cascading failures.**

Think of an electrical circuit breaker:

When too much current flows, the breaker trips and stops the electricity to prevent damage.

Similarly, when a service repeatedly fails, the circuit breaker stops sending requests to it, giving it time to recover.

Instead of waiting for a failing service, the application fails fast and frees up its resources.

## 4. How Does a Circuit Breaker Work?

A circuit breaker has three states:

### 1. Closed (Normal Operation)
- Requests pass through normally.
- The circuit breaker monitors successful and failed requests.
- If failures exceed a configured threshold, it moves to Open.

### 2. Open (Service Is Failing)
- All requests are rejected immediately.
- The failing service is not called.
- This gives the service time to recover and prevents resource exhaustion.

### 3. Half-Open (Checking Recovery)
- After waiting for some time, the circuit breaker allows a few test requests.
- If they succeed → moves to Closed.
- If they fail → moves back to Open.

**Example:**

Suppose the circuit breaker opens after 5 consecutive failures.

1. Closed → Requests pass normally.
2. Open → After 5 failures, requests are blocked.
3. Half-Open → After 30 seconds, a few test requests are allowed.
4. If successful → Closed.
5. If unsuccessful → Open again.

## 5. What Happens When a Request Fails? (Fallback)

A **Fallback is an alternative response or action when the primary service is unavailable.**

Examples:

| Service Failure | Fallback |
|---|---|
| Recommendation Service | Show popular products instead. |
| Review Service | Show product details without reviews. |
| Search Service | Show product categories instead. |
| Payment Processor | Queue the payment for later processing, if the payment flow supports it. |
| Real-time data service | Show cached data instead. |

### Graceful Degradation

**Graceful Degradation means losing some non-essential features while keeping the core functionality working.**

Example:

If Netflix's recommendation service fails, it can show popular or trending titles instead.

Users can still watch videos even though personalized recommendations are unavailable.

## 6. Other Techniques That Improve Resilience

A circuit breaker is only one part of building a resilient system.

| Technique | What It Does |
|---|---|
| Timeouts | Prevents waiting indefinitely for a service response. |
| Retries | Tries a failed request again, preferably with exponential backoff. |
| Circuit Breakers | Stops calling a service that repeatedly fails. |
| Bulkheads | Isolates failures to prevent one operation from affecting others. |
| Fallbacks | Provides an alternative response when the primary service fails. |
| Rate Limiting | Limits incoming requests to prevent service overload. |

### What are Bulkheads?

Bulkheads are inspired by ships, where separate compartments prevent water from flooding the entire ship.

Similarly, in software, bulkheads isolate resources for different operations.

**Example:**

Suppose a User Service handles:
- User Profile
- User Authentication

If profile requests become slow, they should not consume all the resources needed by authentication.

Bulkheads isolate their resources so authentication can continue working.

## 7. Important Circuit Breaker Configurations

A circuit breaker typically has three important configurations:

1. **Failure Threshold:** How many failures or what failure percentage should open the circuit?
   - Example: 50% failures in the last 10 requests.

2. **Open State Timeout:** How long should the circuit remain open before testing recovery?
   - Example: 30 seconds.

3. **Request Volume Threshold:** How many requests should be observed before evaluating the failure rate?
   - Example: At least 20 requests.
   - This prevents a few failures during low traffic from unnecessarily opening the circuit.

## 8. How Do These Techniques Work Together?

A resilient system uses multiple layers of protection:

1. **Timeouts:** Don't wait indefinitely for responses.
2. **Retries:** Retry temporary failures with exponential backoff.
3. **Circuit Breakers:** Stop repeated calls when a service keeps failing.
4. **Bulkheads:** Isolate resources to prevent failures from spreading.
5. **Fallbacks:** Provide alternative responses when the primary service is unavailable.

## 9. Key Takeaways

- **Resilience:** Ability to handle failures without bringing down the entire system.
- **Cascading Failure:** One service failure causes other services to fail.
- **Circuit Breaker:** Temporarily stops requests to an unhealthy service.
- **Closed:** Requests are allowed.
- **Open:** Requests are blocked immediately.
- **Half-Open:** A few test requests check whether the service has recovered.
- **Fallback:** Provides an alternative response.
- **Graceful Degradation:** Keeps core functionality working when non-essential features fail.
- **Bulkheads:** Isolate resources to prevent failures from spreading.

**Remember:** Resilience is the goal. Circuit Breaker is one technique used to achieve it. Combine it with timeouts, retries, bulkheads and fallbacks to build reliable distributed systems.
