# Consistent Hashing

## 1. Problem Statement

Imagine an application running on 3 servers: A, B, and C.

We use a hash function to distribute requests:

`Server = Hash(User ID) % Number of Servers`

**Problem:** When we add or remove a server, the number of servers changes, causing many users to get mapped to different servers.

This results in:
- Existing cached data becoming less useful.
- Cache misses and increased latency.
- Unnecessary redistribution of requests.

**Solution:** Consistent Hashing minimizes the number of requests that need to move when servers are added or removed.

## 2. How Consistent Hashing Works

Instead of using modulo, Consistent Hashing arranges servers and requests on a circular structure called a **Hash Ring**.

1. **Create a Hash Ring:** Imagine a circular ring representing a range of hash values.
2. **Place Servers:** Hash each server's identity to determine its position on the ring.
3. **Place Requests:** Hash each user's ID to determine their position on the same ring.
4. **Find the Server:** Move clockwise from the request's position. The first server encountered handles the request.

**Example:**
- Server A → Position 20
- Server B → Position 50
- Server C → Position 80
- User 101 → Position 25

User 101 is assigned to Server B because it is the first server encountered clockwise.

## 3. What Happens When a Server Is Added or Removed?

**Adding a server:**
- Only requests whose clockwise destination changes are reassigned to the new server.
- Other requests continue going to their existing servers.

**Removing a server:**
- Only requests assigned to the removed server are redistributed.
- Other requests remain unaffected.

**Key Benefit:** Minimal redistribution of requests when the server count changes.

## 4. Virtual Nodes

**Problem:** A physical server might receive more requests than others because server positions on the ring may be unevenly distributed.

**Solution:** Place multiple virtual nodes for each physical server on the ring.

Example:
- Server A → A1, A2, A3
- Server B → B1, B2, B3
- Server C → C1, C2, C3

This improves request distribution and load balancing.

## 5. Use Cases

- Distributed caching.
- Distributed databases.
- Distributed systems for distributing requests across servers.

## 6. Key Takeaway

**Consistent Hashing = Hash Ring + Clockwise Mapping + Minimal Redistribution.**

It ensures that adding or removing servers causes only a small portion of requests to be reassigned, instead of redistributing almost everything.
