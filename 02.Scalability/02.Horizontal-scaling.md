# Horizontal Scaling/ Scaling Down

- Adding more servers to handle more requests.
- Instead of making one server more powerful, we add multiple servers and distribute the workload among them.

## Problem?

A single server has limited CPU, memory, and request-handling capacity. As traffic increases a server may experience:
- High CPU usage.
- Insufficient memory.
- Slower response times.
- Requests timing out.

## 3. How Does Horizontal Scaling Solve It?

- Add more servers and use a **load balancer** to distribute incoming requests across them.
- Each server handles a portion of the workload, increasing the system's overall capacity.

**Example:**

Before scaling:

`1000 requests → [One Server]`

After scaling:

```text
                  ┌──→ [Server 1]
Users → Load      ├──→ [Server 2]
        Balancer ─┼──→ [Server 3]
                  └──→ [Server 4]
```


## When to Choose Horizontal Scaling?

- Traffic is growing rapidly or unpredictably.
- A single server cannot handle the workload.
- You need better availability and fault tolerance.
- You want to scale by adding or removing servers as demand changes.

**Example:** An e-commerce website adds more servers during a big sale.

## 5. When NOT to Choose It?

Avoid or delay it when:
- Traffic is low and one server is sufficient.
- You want the simplest possible architecture.
- Your database or another component remains a bottleneck.
