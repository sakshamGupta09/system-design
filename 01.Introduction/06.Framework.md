# System Design Interview Framework

A structured approach helps you solve unfamiliar system design problems without missing important details.

## The 4-Step Framework

1. **Gather Requirements** — Understand what to build.
2. **High-Level Design** — Identify the major components and their interactions.
3. **Detailed Design** — Explore critical components and design trade-offs.
4. **Scaling and Optimization** — Handle growth, bottlenecks and failures.

## 1. Gather Requirements

**Goal:** Understand what to build before deciding how to build it.

- **Functional Requirements (FRs):** What should the system do?
  - Example: Users can post tweets, follow others and view timelines.
- **Non-Functional Requirements (NFRs):** How well should it work?
  - Example: QPS, latency, availability and number of users.
- **Constraints and Assumptions:** What limitations must we consider?
  - Example: Global or regional service, media support, data retention and budget.

**Key takeaway:** Write down the requirements to guide every design decision.

## 2. High-Level Design

**Goal:** Create a bird's-eye view of the system.

Identify the major components and show how data flows between them.

- **Load Balancer:** Distributes incoming traffic.
- **Application Servers:** Handle business logic.
- **Cache:** Speeds up frequent reads.
- **Database:** Stores persistent data.
- **Message Queue:** Enables asynchronous processing.
- **Object Storage and CDN:** Store and deliver media efficiently.

**Example:** Twitter requests flow from clients through a load balancer to application servers, which interact with caches and databases.

Also, identify the core workflows, such as posting a tweet and generating a timeline.

**Key takeaway:** Focus on the big picture, not implementation details.

## 3. Detailed Design

**Goal:** Understand how the critical components work internally.

Focus on:

- **Database Design:** Schema, relationships and indexes.
- **API Design:** Endpoints, inputs and outputs.
- **Algorithms and Workflows:** How critical operations work.
- **Technology Choices:** Select appropriate databases, caches and queues.
- **Trade-offs:** Explain why you chose an approach and its drawbacks.

### Example: Twitter Timeline Generation

- **Pull Model:** Fetch tweets from followed users when the timeline is requested.
  - Advantage: Simpler writes.
  - Disadvantage: Potentially slower reads.
- **Push Model:** Precompute timelines when tweets are posted.
  - Advantage: Faster reads.
  - Disadvantage: More write work and storage.

A **hybrid approach** can combine both to handle regular users and celebrities with millions of followers.

**Key takeaway:** Explain not just *what* you choose, but *why* and what trade-offs it introduces.

## 4. Scaling and Optimization

**Goal:** Identify bottlenecks and make the system scalable, reliable and cost-effective.

| Problem | Possible Solution |
|---|---|
| High database load | Indexing, caching, sharding |
| Slow reads | Caching, precomputation |
| Traffic spikes | Load balancing, horizontal scaling |
| Hot partitions | Better partitioning and traffic distribution |
| High media delivery cost | CDN, compression, lifecycle policies |

Also consider:

- **Reliability:** Replication, failover and graceful degradation.
- **Monitoring:** Track QPS, latency, error rates and cache hit ratio.
- **Security:** Rate limiting and protection against abusive traffic.
- **Cost Optimization:** Optimize compute, storage and data retention.

**Key takeaway:** Scale based on identified bottlenecks instead of adding infrastructure unnecessarily.

## Interview Checklist

Before finishing, ensure you have covered:

- [ ] Requirements and constraints
- [ ] High-level architecture and data flow
- [ ] Critical components and design trade-offs
- [ ] Bottlenecks, scaling and failure handling

**Remember:** Treat the interview as a collaboration. Clarify assumptions, explain your reasoning and ask the interviewer which components deserve a deeper discussion.
