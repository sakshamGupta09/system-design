# Functional Requirements

- What a system should do from a user's perspective.
- Describe what users can do with the system.

## Example 

Build a chat application. That's not a requirement. That's a vague idea because it does not describe what users can do with the system.

- Users should be able to sign up and log in to their accounts.
- Users should be able to search for other users and start a conversation.
- Users should be able to send and receive messages in real time.
- Users should be able to view their chat history.
- Users should be able to see whether a message has been delivered and read.

## Clarifying Functional Requirements

For each FR, we must dive deeper and gain more clarity on the requirements because that significantly iinfluences our decisions.

- Message type: Can users send text, images, videos, or files?
- Can they be edited after sending?
- Can sent messages be deleted?


## Technique to gather FR properly

- Who is using the system and how. For an e-commerce app, users can be buyers, sellers and admins. Each has different needs. Gather the detailed information.
- Understanding scope and boundaries. We cannot build everything at once. So, we must identify the must-haves and nice-to-haves. Defining the MVP.
- FR should be measurable and testable. Instead of "Users should be able to upload a video quickly", "Users should be able to upload a 100MB video within 2 minutes on a standard broadband connection."
