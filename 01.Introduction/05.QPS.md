# QPS and Server Estimation

- Estimate the incoming work per day, estimate how much work one server can do, and calculate how much capacity you need and the cost.
- QPS tells us how many requests a system handles per second.

### Calculate Average QPS

**Formula:**

Average QPS = Total daily requests ÷ 86,400

For easier mental math, approximate 86,400 seconds as 100,000.

**Example:**

- 1 million daily active users.
- Each user reads 100 tweets per day.

Daily requests = 1 million × 100 = 100 million.

Average QPS = 100 million ÷ 100,000 = **1,000 QPS**.

### Average QPS vs. Peak QPS

Traffic is not uniform throughout the day. During peak hours or major events, requests increase.

For estimation, assume peak traffic is 2–3 times the average.

**Peak QPS = Average QPS × Peak multiplier**

Example: 1,000 × 3 = **3,000 peak QPS**.

The multiplier depends on the system's traffic patterns.

### Read QPS vs. Write QPS

- **Read:** Fetching data, such as reading a tweet.
- **Write:** Creating or updating data, such as posting a tweet.

Suppose a system handles 300,000 read QPS and 5,000 write QPS.

Read-to-write ratio = 300,000 ÷ 5,000 = **60:1**.

This means 60 reads occur for every write. Read-heavy systems often benefit from caching and read replicas.

## 3. Server Estimation

Once we estimate peak traffic, we can calculate how many servers are needed.

**Formula:**

Required servers = Peak QPS ÷ Capacity per server

Server capacity depends on the workload, hardware, and performance requirements.

**Example:**

- Peak traffic = 10,000 QPS.
- One server handles 2,000 QPS.

Required servers = 10,000 ÷ 2,000 = **5 servers**.

This is the theoretical minimum. Real systems need extra capacity.

### Account for Utilization and Redundancy

Servers should not run at full capacity all the time. Spare capacity helps handle traffic spikes and maintain response times.

If we target 70% utilization:

Effective capacity per server = 2,000 × 70
