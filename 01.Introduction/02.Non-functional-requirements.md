# Non-Functional Requirements (NFRs)

- How well a system should work. 

## Most Important NFRs

## 1. Performance

How quickly does the system respond to requests?

- Measured using latency (response time) and throughput (requests processed per second).
- Example: 99% of API requests should respond within 200 ms.

## 2. Scalability

- The system should handle growing demand without significant performance degradation.
- Example: Support 10,000 concurrent users without exceeding the target response time.

## 3. Availability

- How often is the system operational and accessible to users?
- Availability is expressed in nines. More nines mean less permitted downtime.

| Availability         | Approx. downtime per year |
| -------------------- | ------------------------- |
| 99% (two nines)      | 3.65 days                 |
| 99.9% (three nines)  | 8.76 hours                |
| 99.99% (four nines)  | 52.6 minutes              |
| 99.999% (five nines) | 5.26 minutes              |

## 4. Reliability

How consistently does the system work correctly, even when failures occur?

- A reliable system handles failures gracefully and avoids data loss or incorrect results.
- Example: A database failure should not cause confirmed transactions to be lost.


## Make NFRs Measurable

Avoid vague statements such as "The system should be fast" or "The system should be scalable."

Instead, define specific, measurable targets.

- Performance: 99% of API requests must respond within 200 ms under a load of 5,000 requests per second.
- Scalability: The system must support 10,000 concurrent users without exceeding its latency target.
- Availability: The system must maintain 99.99% monthly availability.
- Reliability: Confirmed transactions must not be lost when an application server or DB server crashes.
