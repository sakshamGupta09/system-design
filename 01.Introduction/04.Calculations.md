# System Design Calculations

Back-of-the-envelope calculations help us **estimate a system’s storage, bandwidth, QPS, and server requirements** quickly, without relying on exact data or a calculator.

The goal is to estimate the **order of magnitude**, not the exact number.

## 1. Storage Units

For quick calculations, use powers of 10.

| Unit | Approximate size |
|---|---:|
| 1 KB | 1,000 bytes |
| 1 MB | 1,000 KB |
| 1 GB | 1,000 MB |
| 1 TB | 1,000 GB |
| 1 PB | 1,000 TB |
| 1 EB | 1,000 PB |

**Quick tip:** Each step up multiplies the size by 1,000 (three zeros).

## 2. Common File Sizes

Memorize these rough estimates for system design interviews.

| Data type | Approximate size |
|---|---:|
| 1 text character | 1 byte (typically) |
| Short text post (300 characters) | 300 bytes |
| Smartphone photo | 4 MB |
| HD video (per minute) | 50 MB |
| 4K video (per minute) | 300 MB |

Actual sizes vary depending on encoding, compression, resolution, and metadata.

## 3. Storage Estimation

**Formula:**

Storage per day = Items created per day × Average size per item

### Example: Social Media Posts

Assume a platform generates:
- 500 million text posts per day.
- Average post size: 300 bytes.
- 10% of posts include an image.
- Average image size: 4 MB.

**Text storage:**

500 million × 300 bytes ≈ **150 GB/day**

**Image storage:**

50 million × 4 MB ≈ **200 TB/day**

**Key insight:** Images require far more storage than text.

### Example: Annual Storage Growth

If a platform stores 4 PB of new photos daily:

- Daily storage: 4 PB
- Annual storage: 4 × 365 ≈ **1.5 EB**
- Five-year storage: 1.5 × 5 ≈ **7.5 EB**

This excludes videos, metadata, backups, and replication.

## 4. Replication and Backups

Production systems often keep multiple copies of data for availability and durability.

- If three total copies are required, multiply the primary storage by 3.
- Example: 7.5 EB × 3 = **22.5 EB** of total stored copies.
